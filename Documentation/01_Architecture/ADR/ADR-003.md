Architektura zapisu oparta o JSON

# Kontekst

Gra wymaga obsługi zapisu i odczytu stanu.

Należało zdecydować:

- jeden plik,
- wiele plików,
- baza danych.

# Decyzja

Zapis zostaje podzielony.

Struktura:

- `save/`
- `slot1/`
- `player.json`
- `world.json`
- `inventory.json`
- `meta.json`

Zapisywany jest pełny stan świata.

Nie wykorzystujemy seedów.

# Uzasadnienie

Korzyści:

- prostsza implementacja,
- łatwiejszy debug,
- mniejsze ryzyko uszkodzenia danych.

# Konsekwencje

Pozytywne:

- czytelny zapis,
- łatwe migracje.

Negatywne:

- więcej plików.

# Alternatywy

Jeden `save.json`.

Odrzucono z powodu:

- dużej odpowiedzialności jednego pliku.
